# NewMarket

NewMarket is a campus-focused multi-vendor marketplace built with React, Express, Prisma, and SQLite. Stores, products, accounts, orders, and fulfillment updates are persisted in the database.

## Requirements

- Node.js 18 or newer
- npm
- A Paystack account for payment processing
- A Cloudinary account for hosted image uploads

## Local setup

1. Install dependencies:

   ```powershell
   npm install
   ```

2. Create a local environment file and replace the provider placeholders:

   ```powershell
   Copy-Item .env.example .env
   ```

   Set a unique `JWT_SECRET` with at least 32 characters. Configure `DATABASE_URL`, Paystack, and Cloudinary values as described below. Never commit `.env` or put provider secrets in frontend code.

3. Generate the Prisma client and create/update the SQLite database:

   ```powershell
   npm run prisma:generate
   npm run prisma:push
   ```

4. Start the API and frontend in separate terminals:

   ```powershell
   npm run server
   npm run dev
   ```

   The frontend is available at `http://localhost:3000`; the API listens on port `5000`.

   The local database starts empty. Register as a vendor, create a storefront, and publish products to populate the marketplace.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | Prisma database URL. The local default is `file:./dev.db`. |
| `JWT_SECRET` | Random server-only secret used to sign authentication tokens; use at least 32 characters. |
| `PORT` | Optional API port (defaults to `5000`). |
| `PAYSTACK_SECRET_KEY` | Secret test/live API key from the Paystack dashboard. |
| `PAYSTACK_CALLBACK_URL` | Browser return URL after checkout (defaults to `http://localhost:3000/payment/callback`). |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary cloud name. |
| `CLOUDINARY_API_KEY` | Cloudinary API key. |
| `CLOUDINARY_API_SECRET` | Cloudinary API secret. |

Create the Paystack and Cloudinary accounts in their respective provider dashboards and copy the credentials into the local server environment; keys cannot be generated by this repository. Configure the Paystack webhook URL as `https://<your-api-host>/api/v1/payments/webhook` and subscribe to `charge.success`. Use test keys and a reachable webhook URL when testing.

Paystack checkout creates a pending order, then redirects the buyer to Paystack. The callback and webhook both verify the transaction against Paystack's API; the order only becomes `PAID` when the reference, amount, currency, order ID, and successful transaction status match. The webhook also validates Paystack's HMAC signature. The integration does not implement escrow custody, split settlements, vendor payouts, or refunds.

Cloudinary credentials enable authenticated `POST /api/v1/uploads` image uploads. Images are limited to 5 MB and JPG, PNG, WEBP, or GIF. Store registration and product creation accept uploaded image files; an image URL can also be supplied for products.

## Administrator access

Public registration only creates `BUYER` or `VENDOR` accounts. To grant administrator access, sign in to Prisma Studio (`npm run prisma:studio`) and change the intended user's `role` to `ADMIN`. The `/admin` page and `/api/v1/admin/overview` endpoint are both protected; the server checks the database role on every authenticated request.

## API overview

All routes use the `/api/v1` prefix.

| Method | Route | Access |
| --- | --- | --- |
| `GET` | `/health` | Public |
| `POST` | `/auth/register` | Public |
| `POST` | `/auth/login` | Public |
| `GET` | `/auth/me` | Authenticated |
| `GET` | `/stores` | Public |
| `POST` | `/stores` | Authenticated |
| `GET` | `/products` | Public |
| `POST` | `/products` | Store owner or admin |
| `POST` | `/uploads` | Authenticated |
| `POST` | `/orders/checkout` | Authenticated |
| `GET` | `/payments/verify/:reference` | Authenticated order owner |
| `POST` | `/payments/webhook` | Paystack signature verified |
| `GET` | `/orders/my-orders` | Authenticated buyer |
| `GET` | `/vendor/orders` | Vendor or admin |
| `PATCH` | `/vendor/orders/:id/status` | Owning vendor or admin |
| `GET` | `/admin/overview` | Admin |

## Available scripts

- `npm run dev` — Start the Vite frontend
- `npm run build` — Build the frontend for production
- `npm run preview` — Preview the production build
- `npm run server` — Start the Express API
- `npm run prisma:generate` — Generate the Prisma client
- `npm run prisma:push` — Apply the Prisma schema to the configured database
- `npm run prisma:studio` — Open Prisma Studio
